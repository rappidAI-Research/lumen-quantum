# Application readiness checklist

Use this checklist before submitting the
[OpenAI Codex for Open Source application](https://openai.com/form/codex-for-oss/).
It does not guarantee selection.

## Repository

- [x] The open-source-readiness pull request is reviewed and merged (`7e9cb34`).
- [ ] Confirm the newest CI run is green on `main` after the Dependabot dependency-range updates (`da79ca8`).
- [ ] Required CI is green on the default branch.
- [ ] The repository description identifies the actual technical scope.
- [ ] README setup and CPU-safe verification commands work from a clean clone.
- [ ] Source/documentation licensing is approved and unambiguous.
- [ ] Model, tokenizer, dataset, and third-party license boundaries are visible.
- [ ] Security policy, governance, maintainer, support, and contribution files
  are present on the default branch.
- [ ] Genuine unresolved work is represented by specific issues, not artificial
  activity.

## Evidence

- [ ] Recheck public stars, forks, open issues, followers, and repository count.
- [ ] Record retrieval date and direct public source for every metric.
- [ ] Confirm no downloads, users, contributors, benchmarks, or adoption are
  inferred from missing data.
- [ ] Link the technical repository, relevant CI run, draft/released version,
  roadmap, and maintainer plan where the form permits.
- [ ] Distinguish publisher-reported historical results from independently
  reproducible evidence.

## Answers

- [ ] Recount all four answer fields after any edit; each must remain at or below
  500 Unicode characters.
- [ ] Keep the primary/sole-maintainer statement accurate.
- [ ] Keep the explicit low-adoption disclosure unless public metrics change.
- [ ] Describe concrete maintenance uses, not speculative product capabilities.
- [ ] State that human review controls merges, licensing, releases, and external
  publication.

## Maintainer approval

- [ ] Review [openai-codex-for-oss.md](openai-codex-for-oss.md) word for word.
- [ ] Confirm the application form's current eligibility and privacy terms.
- [ ] Confirm the account and repository names entered are public and correct.
- [ ] Approve submission as truthful and current.
- [ ] Submit manually; record the submission date without publishing private
  application correspondence or account data.

Do not submit automatically from this repository workflow.
